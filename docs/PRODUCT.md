## 1. 问题

现有的 iPad 阅读方案没有一款同时做好三件事：

1. **把论文/教材变成能读的东西**——双栏 PDF 在窄屏上被迫缩放拖动；公式、图表、代码在重排中被打散；
2. **数据全在用户手里**——主流阅读器要么云优先（内容与批注在别人的服务器上），要么导出受限；
3. **阅读产出能回流**——高亮和笔记躺在 app 里，回不到用户的笔记系统。

由此产生的具体损失：读得累（回行错误、理解中断）、读不进去（入口摩擦）、读了白读（批注不可复用）。

## 2. 目标用户

- **主用户（定义产品的那个）**：在平板（iPad）上读**小说、教材、论文**的中文用户。自有文件库（EPUB / TXT / PDF），阅读时间长、对排版敏感，讨厌在缩放和拖动里读书。
- **次用户**：只需要一个"打开就能好好读"的本地阅读器的普通读者。
- 非目标用户：只看商城正版书的消费者（他们用微信读书/Apple Books，且我们不与之竞争）。

**核心场景三条**：① 一本小说/EPUB 连续读几小时；② 一本教材（PDF 或 EPUB）对照翻阅、做记号；③ 一篇论文（双栏 PDF）在窄屏上读得下去。

笔记软件（Obsidian、飞书知识库等）是**未来的可选出口**，不是产品前提——产品不为任何一方的格式做假设。

## 3. 竞品与生态位

| 类别 | 代表 | 缺陷（设计上无法弥补的） |
|---|---|---|
| 系统/生态 | Apple Books、Kindle | 锁商店；自有库进不去；批注出不来 |
| 云阅读 | Readwise Reader、Matter | 云优先、订阅；PDF 重排有限；数据不属于用户 |
| 本地阅读 | Yomu、KyBook、PDF Expert | 无重排；导出受限；无同步 |
| 专业标注 | MarginNote、LiquidText | 纸张模型；无重排；私有格式 |
| 中文系 | 微信读书、掌阅 | 云书城逻辑；本地库无法进入 |
| 开源 | KOReader | 强，但无 iPad 版；触屏 UX 差 |

**生态位**：把「移动端 PDF 重排 × 本地优先 × 批注回流笔记系统」三者同时做完整的，目前不存在。
GitHub 佐证：Rust 生态中 `pdf reflow` 相关仓库全部为 0★ 停更项目；`epub reader` 有 1.2k★ 级项目但全在终端/墨水屏；移动端 Rust 阅读器为零。

## 4. 定位

> **一个先把书读好的平板阅读器：本地文件进，舒服的排版、PDF 重排、离线读完；批注一键导出成 Markdown。**

三层结构，第 1 层是本体与第一目标，其余是为它服务的（可延后、可不要）：

1. **阅读器（发行主体，第一目标）**：导入（本地文件 / 系统分享 / 隔空投送）→ 阅读（EPUB/TXT 排版 + PDF 重排）→ 批注 → 导出 Markdown（系统分享面板 / 文件导出）。
2. **笔记软件接入（第二期，可选出口）**：批注回流到 Obsidian 仓库 / 飞书知识库 / 其他 Markdown 知识库。
3. **源（source）层（第二期起）：可插拔内容来源**：OPDS / WebDAV 等标准协议；规则源更晚，且不预置。

## 5. 设计原则（决定一切取舍）

### 5.1 阅读体验 = 阅读器消失

唯一总判据：**读完一章后记得的是内容，不是 UI。** 一切设计决策用两条过滤器检验：

- 它让眼睛少做功了吗？
- 它让读者少做决定了吗？

两者都不满足 → 砍掉。

### 5.2 好阅读体验的操作化指标

| 维度 | 口径 |
|---|---|
| 正文度量 | 西文 45–75 字符/行；中文 25–40 字/行；行距 1.5–1.7；边距可调且跟随用户而非书本 |
| 重排正确性 | 公式/图/表/代码为不可分割原子块；双栏正确重排为单列；阅读顺序错误率 < 1/页 |
| 连续性 | 长文默认滚动；返回上次位置零误差；字号/旋转/重启后位置不变 |
| 零阻塞 | 点开即渲染；无启动页、无对话框；冷启动 < 500ms 出首屏 |
| 跳转 | 目录/书签/进度跳转 < 1s 完成；返回成本 < 1s |
| 标注 | 选中到完成高亮 ≤ 3 步；不离开正文；笔记可输入 |
| 中文排版 | 全角标点、悬挂标点、中英自动间距、简繁正确 |
| 位置记忆 | 以语义锚点保存（章节+段落偏移），不依赖页码 |
| 零打断 | 阅读中绝不弹任何提示；失败静默重试；第一期阅读不依赖网络 |

### 5.3 反模式（明确不做）

- 翻页动画、纸张拟物、书脊阴影；
- 每本书单独设置排版（排版属于用户与设备，不属于书）；
- 把"查看大图"作为公式/图表的呈现方式（原子块应随文流动）；
- 阅读中弹窗：同步失败、电量、更新、推荐；
- 把批注工具做成一级入口（那是书评家，不是学习者）。

## 6. 功能范围

### 6.1 第一期（MVP）

| # | 功能 | 说明 | 验收口径 |
|---|---|---|---|
| 1 | 本地导入 | 系统文件 / 隔空投送 / 分享导入；EPUB / TXT / PDF | 打开即读 |
| 2 | **EPUB / TXT 阅读** | 排版（字号/行宽/行距/边距/字体）、主题（日/夜/纸）、滚动长文、进度保存 | CR-8 |
| 3 | **PDF 重排** | 双栏检测 → 单列流式；原子块保护（公式/图/表/代码） | CR-1、CR-2 |
| 4 | 连续性 | 语义锚点位置记忆；字号/旋转/重启位置不变 | CR-3 |
| 5 | 批注 | 高亮 / 笔记 / 书签；3 步内完成 | CR-4 |
| 6 | 批注导出 | Markdown（原文引用 + 出处 + 定位）；系统分享面板 / 文件导出 | CR-9 |
| 7 | 离线 | 全功能离线；零可见错误提示 | CR-6（离线部分） |

### 6.2 第二期

- 笔记软件接入：Obsidian 仓库 / 飞书知识库 / 其他 Markdown 知识库（优先级最高）；
- 桌面伴生 + 局域网同步（书库索引、批注回流）；
- OPDS / WebDAV 源；规则源更晚（声明式规则引擎：CSS/JSONPath/正则/分页模板，**不支持任意代码**，不预置任何源）；
- 本地 AI：选中即离线翻译、公式/代码保真提取；
- 手机端布局。

### 6.3 明确不做

- **书城**。内容/合规/支付/运营四重成本，且与产品价值无关。
- 社交、推荐、阅读排行榜；
- 云优先账号体系（同步可以要，服务器不是你的就不是你的）；
- 自研 PDF 渲染引擎（使用现有渲染库，把工程投入放在重排与阅读体验上）；
- 桌面 GUI 客户端（伴生程序若做，是纯 CLI + 状态页）。

## 8. 里程碑

| 阶段 | 目标 | 可验证成果 |
|---|---|---|
| M1 · 引擎 | 阅读引擎在桌面成立 | CLI：`cadmus-cli` 将双栏论文、EPUB、TXT 输出为可读单列/分页；CR-1/2/8 的自动化部分通过 |
| M2 · Android | 真机可读可批注 | 双栏论文与小说在 Android 上连续读完；批注导出 Markdown（CR-3/4/9） |
| M3 · iOS | iPad 真机 | TestFlight 包；iPad 全部验收通过 |
| M4 · 笔记接入 | 批注回流域（第二期） | Obsidian 仓库 / 飞书出现对应 Markdown（CR-5） |
| M5 · 源 | OPDS/WebDAV（第二期） | 从 OPDS 目录下载并阅读 |

里程碑排序原则：**先把书读好，再把笔记送出去。** 任一阶段，阅读体验的修复优先于新功能。

## 9. 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| iOS 构建依赖 macOS（Linux 无法本地出包） | 高 | CI 用 GitHub Actions macOS runner；本地只做 Android |
| 重排质量达不到"能连续读" | 高 | M1 桌面先行验证；CR-1 为 go/no-go 门 |
| PDF 渲染库依赖（AGPL/预编译二进制） | 中 | 隔离在单一 crate，可替换 |
| 长期维护（阅读器是长跑） | 中 | 从"每天自己用"起步；输入源天然持续 |
| 中文排版细节（禁则、悬挂） | 中 | 明确列入 CR，不靠后期补 |
| EPUB 阅读体验做不出辨识度（读者已有优质 EPUB 阅读器） | 中 | 以真实小说做长时段对照试读；"阅读体验不输主流，PDF 重排明显更强"为最低标准 |
