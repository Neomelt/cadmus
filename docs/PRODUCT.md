## 1. 问题

现有的 iPad 阅读方案没有一款同时做好三件事：

1. **把论文/教材变成能读的东西**——双栏 PDF 在窄屏上被迫缩放拖动；公式、图表、代码在重排中被打散；
2. **数据全在用户手里**——主流阅读器要么云优先（内容与批注在别人的服务器上），要么导出受限；
3. **阅读产出能回流**——高亮和笔记躺在 app 里，回不到用户的笔记系统。

由此产生的具体损失：读得累（回行错误、理解中断）、读不进去（入口摩擦）、读了白读（批注不可复用）。

## 2. 目标用户

- **主用户（定义产品的那个）**：需要在 iPad 上读论文、教材、技术书的中文用户。自有 PDF/EPUB 库（Zotero、Calibre、本地文件夹），有 Obsidian/知识库类笔记系统，重度吃狗粮。
- **次用户**：同样有本地书库、对主流阅读器不满意的技术用户。

非目标用户：只读正版商城书的普通消费者（他们用微信读书/Apple Books，且我们不与之竞争）；不需要笔记回流的休闲读者。

## 3. 竞品与生态位

| 类别 | 代表 | 缺陷（设计上无法弥补的） |
|---|---|---|
| 系统/生态 | Apple Books、Kindle | 锁商店；自有库进不去；批注出不来 |
| 云阅读 | Readwise Reader、Matter | 云优先、订阅；PDF 重排有限；数据不属于用户 |
| 本地阅读 | Yomu、KyBook、PDF Expert | 无重排；导出受限；无同步 |
| 专业标注 | MarginNote、LiquidText | 纸张模型；无重排；私有格式 |
| 中文系 | 微信读书、掌阅 | 云书城逻辑；本地库无法进入 |
| 开源 | KOReader | 强，但无 iPad 版；触屏 UX 差 |

**生态位**：把「移动端 PDF 重排 × 本地优先 × 批注回流笔记系统」三者同时做完整的，目前不存在。
GitHub 佐证：Rust 生态中 `pdf reflow` 相关仓库全部为 0★ 停更项目；`epub reader` 有 1.2k★ 级项目但全在终端/墨水屏；移动端 Rust 阅读器为零。

## 4. 定位

> **一台把论文和书变好读的平板阅读器，和一个让笔记回到你知识库的管线。**

产品由三层构成，其中第 1 层是发行的主体：

1. **App（iOS/Android，发行主角）**：导入 → 重排阅读 → 批注 → 批注回流。
2. **桌面伴生程序（Rust，可选）**：索引桌面书库（`lunwen`/`Zotero`/Calibre 目录），局域网同步，接收批注写入知识库 Inbox。
3. **源（source）层**：可插拔的内容来源。第一期：本地文件、OPDS、WebDAV；规则源第二期。

## 5. 设计原则（决定一切取舍）

### 5.1 阅读体验 = 阅读器消失

唯一总判据：**读完一章后记得的是内容，不是 UI。** 一切设计决策用两条过滤器检验：

- 它让眼睛少做功了吗？
- 它让读者少做决定了吗？

两者都不满足 → 砍掉。

### 5.2 好阅读体验的操作化指标

| 维度 | 口径 |
|---|---|
| 正文度量 | 西文 45–75 字符/行；中文 25–40 字/行；行距 1.5–1.7；边距可调且跟随用户而非书本 |
| 重排正确性 | 公式/图/表/代码为不可分割原子块；双栏正确重排为单列；阅读顺序错误率 < 1/页 |
| 连续性 | 长文默认滚动；返回上次位置零误差；字号/旋转/重启后位置不变 |
| 零阻塞 | 点开即渲染；无启动页、无对话框；冷启动 < 500ms 出首屏 |
| 跳转 | 目录/书签/进度跳转 < 1s 完成；返回成本 < 1s |
| 标注 | 选中到完成高亮 ≤ 3 步；不离开正文；笔记可输入 |
| 中文排版 | 全角标点、悬挂标点、中英自动间距、简繁正确 |
| 位置记忆 | 以语义锚点保存（章节+段落偏移），不依赖页码 |
| 同步 | 失败静默重试；阅读中绝不弹任何提示 |

### 5.3 反模式（明确不做）

- 翻页动画、纸张拟物、书脊阴影；
- 每本书单独设置排版（排版属于用户与设备，不属于书）；
- 把"查看大图"作为公式/图表的呈现方式（原子块应随文流动）；
- 阅读中弹窗：同步失败、电量、更新、推荐；
- 把批注工具做成一级入口（那是书评家，不是学习者）。

## 6. 功能范围

### 6.1 第一期（MVP）

| 功能 | 说明 | 验收口径 |
|---|---|---|
| 本地导入 | 系统文件、隔空投送、文件共享 | PDF 打开即读 |
| **重排阅读** | 双栏检测 → 单列流式；原子块保护；字号/边距/暗色 | CR-1、CR-2 |
| 连续性 | 语义锚点位置记忆；滚动阅读 | CR-3 |
| 批注 | 高亮/笔记/书签；3 步内完成 | CR-4 |
| **批注回流** | 导出 Markdown（原文引用 + 出处 + 定位）到知识库 Inbox | CR-5 |
| OPDS / WebDAV | 标准协议源；离线缓存 | CR-6 |
| 桌面伴生（可选） | 索引书库 + 局域网同步 + 回流写盘 | CR-5 |

### 6.2 第二期

- EPUB 支持（EPUB 本身可重排，优先级低于 PDF）；
- 规则源（声明式规则引擎：CSS/JSONPath/正则/分页模板，**不支持任意代码**，不预置任何源）；
- 本地 AI：选中即离线翻译、公式/代码保真提取；
- 手机端布局。

### 6.3 明确不做

- **书城**。内容/合规/支付/运营四重成本，且与产品价值无关。
- 社交、推荐、阅读排行榜；
- 云优先账号体系（同步可以要，服务器不是你的就不是你的）；
- 自研 PDF 渲染引擎（使用现有渲染库，把工程投入放在重排与阅读体验上）。

## 8. 里程碑

| 阶段 | 目标 | 可验证成果 |
|---|---|---|
| M1 · 引擎 | 重排引擎在桌面成立 | CLI：`reader reflow a.pdf` 输出可读单列，双栏论文验收通过（CR-1） |
| M2 · Android | 真机可读可批注 | 双栏论文在 Android 上连续读完；批注导出 Markdown（CR-2/4/5） |
| M3 · iOS | iPad 真机 + 还原度 | TestFlight 包；iPad 验收全部通过 |
| M4 · 同步 | 桌面伴生 + 回流闭环 | 高亮 3 处 → 桌面 Inbox 出现 3 条 Markdown（CR-5） |
| M5 · 源 | OPDS/WebDAV | 从 OPDS 目录下载并阅读 |

## 9. 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| iOS 构建依赖 macOS（Linux 无法本地出包） | 高 | CI 用 GitHub Actions macOS runner；本地只做 Android |
| 重排质量达不到"能连续读" | 高 | M1 桌面先行验证；CR-1 为 go/no-go 门 |
| PDF 渲染库依赖（AGPL/预编译二进制） | 中 | 隔离在单一 crate，可替换 |
| 长期维护（阅读器是长跑） | 中 | 从"每天自己用"起步；输入源天然持续 |
| 中文排版细节（禁则、悬挂） | 中 | 明确列入 CR，不靠后期补 |
